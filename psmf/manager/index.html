PSMF Manager: what it actually does

A web app by PVCON Consulting (Mumbai) that stores the master file section by section instead of as one Word document, and runs every edit through a review step.

Tracked changes

What it does

Shows every proposed edit to a section as a redline: green for added text, red strikethrough for removed text, with a count of changes.

Under the hood

The file is stored as rich text per sub-section inside the app, not as a Word file. It keeps the last approved text and the proposed text and renders a word-level comparison between them.

Limits

Standard feature of any document tool. The value is only that it exists inside a PSMF-shaped structure.

Change requests per sub-section

What it does

Every edit is a request on one numbered sub-section, here "3.1 Overview of Main Sources of Safety Data". The reviewer sees who asked and when, the status, and can Edit, Approve or Reject. Tabs: Changes, Preview, Ask AI, Comments, Activities.

Under the hood

Works like a pull request in GitHub, scoped to one sub-section. Each request has an author, timestamp, status (Requested → Approved/Rejected), a diff, comments and an activity history. Approving merges the text into the current draft version.

Limits

Not shown: what happens if two people open requests on the same sub-section at once. No sign of automatic conflict handling.

AI review of a change

What it does

The reviewer clicks "Ask AI for Feedback". The AI comments on whether the edit fits the sub-section and the EU guidance, flags risky deletions, and can rewrite the text with "Apply AI Suggestions". A note warns that the AI can be wrong.

Under the hood

An LLM call with the sub-section text, the proposed change and GVP Module II guidance, returning free-text critique and an optional rewrite. Scope is one change in one sub-section.

Limits

Doesn't look at the rest of the file, so it can't notice that the same fact now contradicts another section. AI provider and where data is processed: not disclosed.

AI-drafted change log entry

What it does

Step 2 of every edit is "Change Log Details". A tick box decides whether the change goes into the official change log (Annex I). The AI fills in the reason for the change and a description.

Under the hood

An LLM summarises the diff into two required fields. Entries are stored per change request and compiled into the Annex I table when the file is generated.

Limits

Genuinely useful: removes the tedious part of writing the log. Still one entry per sub-section edit, not per real-world event.

Version history

What it does

Older versions of the file can be opened read-only from a dropdown (5.3, 5.4, 5.5 current). The header shows the current draft number and the data lock point date.

Under the hood

Each approved version is kept as an immutable snapshot. New drafts are created by unlocking the latest version.

Limits

Standard. Meets the requirement to show what the file said at a past date.

One-click document generation

What it does

Compiles the approved sections and annexes into a finished PDF with bookmarks, with a progress bar.

Under the hood

Server-side rendering of structured content into a fixed template, run as a background job. Bookmarks per section and annex.

Limits

"Compliance checks" during generation are mentioned but not explained anywhere.

Global and local files

What it does

One company can hold several files: a global one plus local ones (UK, India, Saudi Arabia, China, Egypt). Each has its own version number and next generation date, with "Mapping" and "Manage" buttons.

Under the hood

Multiple documents per company account. "Mapping" likely links global sections to local ones so shared content is inherited. Suggests one account per client company; a consultancy would need the multi-client tier.

Limits

Useful for big companies with many country files. For a consultant with one client and an EU plus maybe a UK file, a minor benefit.

"Plug into your ecosystem"

What it does

A diagram of storage types: cloud, data lakes, shared drives, file systems, PV platforms.

Under the hood

These are generic categories, not named connectors. The feature page describes the actual mechanism: connected repositories are checked via webhooks or APIs, by default every 24 hours; an updated file either creates a change request or is copied in automatically.

Limits

Syncs files, not facts. It can notice that a spreadsheet changed; it can't know that a new distributor means edits in three sections. No named integrations (for example SharePoint) are shown.
